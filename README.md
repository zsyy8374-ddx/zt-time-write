# zt-time-write · 涨停时间写入

涨停时间写入通达信**外部数据 ID=114**：从同花顺问财查询「最终涨停时间」，写入通达信 `extern_user.txt`，并自动注册 `datacfg.dat`（ID=114「涨停时间」，type=0 外部/字符串数值）。

## 触发词

董哥说「涨停时间写入」或「跑zt_time_write」。

## 运行

```bash
python3 zt_time_write.py            # 默认最新交易日
python3 zt_time_write.py 20260615   # 指定日期
```

## ST 股说明（2026-09-05 董哥确认）

**不再过滤 ST**：ST/*ST 股涨停同样写入 ID=114。
- 主板 ST 涨跌幅限制 = 10%，科创板/创业板 ST = 20%
- 问财条件：`最终涨停时间[日期], 涨停, 非停牌, ...`（仅排除停牌，不再排除 ST）

## 数据源

- 同花顺问财：`最终涨停时间[日期], 涨停, 非ST, 非停牌, 代码[日期], 股票简称`
- 账号：thsdk 正式账号（zsyyddx），经 `ths_config.py`（get_ths_ops）读取本地配置，**密码不入库**

## 写入格式

`extern_user.txt` 文本行（GBK/UTF-8）：
```
市场标志|代码|114|HHMMSS|0.000
```
- 市场标志：6/8开头→1(沪/科创)，0/3开头→0(深/创业)，9开头→2(北交所)，4/8开头北交所→2
- 覆盖策略：写前删除旧的 `|114|` 行再写新行（其它ID数据保留）
- 时间格式：6位数字 HHMMSS

`datacfg.dat`：自动注册/确保 ID=114 名称「涨停时间」（120B/条记录格式，插在 ID=113 之后，ref=115）。

## 写入前清空已有数据

每次运行都会先清空 ID=114 的旧数据再写入：
- `extern_user.txt`：删除所有已存在的 `|114|` 行（字节级操作，不碰其它ID的GBK内容）
- `datacfg.dat`：删除 ID=114 旧注册记录后重新注册（保证唯一干净）

## ⚠️ 铁律

**通达信运行中写 extern_user.txt / datacfg.dat，重启时会被通达信内存缓存整体覆盖！**
- 正确流程：通达信**完全退出** → 写入 → 再打开
- 若通达信正在运行且近期要重启，重启前重跑一次本脚本
